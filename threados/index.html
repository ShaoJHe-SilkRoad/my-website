AUV 0.15.1 · build 2026101002. Download, checksum and release limits / 下载、哈希与版本限制.

ThreadOS

Choose once. Copy once. Your Leader handles the bound team.

ThreadOS is the team-settings workspace inside AUV — Agent Usage Viewer, formerly UMA. It prepares a deterministic instruction for your existing native agents. It does not host another agent engine or automatically send tasks.

Install or upgrade AUV

AUV 0.15.1 / build 2026101002 includes ThreadOS and Sectorium in one application. Do not download separate module apps.

1. Requirements and downloads

  • macOS 14 or later, Apple silicon Mac (M-series). Check Apple menu → About This Mac. There is no Intel binary in this release.
  • Download AUV-0.15.1-build2026101002.zip and HASHES.txt from the release. GitHub’s automatically generated “Source code” archives are not installable applications.
  • The distribution is signed by Developer ID Application: SHAOTING HE (C6TUZVJ6SJ), accepted by Apple notarization and stapled. This describes the released archive, not storage validation on your computer.

Expected archive SHA-256:

598bd61b8a439dde426b943bee3f84e57ad46bba96b94747405ae687825d505e

Optional verification, when the original filename is in Downloads: run the following read-only command in Terminal and compare its first 64 characters with this value and HASHES.txt. Stop and download again if they differ.

shasum -a 256 ~/Downloads/AUV-0.15.1-build2026101002.zip

2. First installation

  1. Double-click the ZIP in Finder to extract UMA.app. Do not open its package contents or run source/build scripts to install it.
  2. Move it to the internal disk’s Applications folder (/Applications) or your personal Applications folder (~/Applications). Choose one location and keep using it. Complete any normal system approval needed for copying there.
  3. Open the installed copy, rather than the copy in Downloads or a temporary folder. Required Sectorium controls must not depend on an external drive you intend to eject.
  4. Respond to a normal macOS first-open confirmation after checking the source. If macOS reports damage, an unverifiable application or a security-policy block, download again and verify the hash. Do not disable Gatekeeper, remove quarantine attributes or change security settings to force it open.
  5. Open AUV → About AUV and check 0.15.1, build 2026101002. If only the version is shown, check the installed UMA.app with Finder → Get Info; the detailed build identity is also in the release’s RELEASE-MANIFEST.json. If an older version appears, quit that copy normally and open the intended installation.

3. Upgrade from UMA or an older AUV

  1. Save your work and quit the old application through its menu. Closing a window may leave its menu-bar process running.
  2. Retain the old UMA.app in a separate backup folder on the internal disk. Do not overwrite your only old-version backup.
  3. Copy the new UMA.app into the same installation location you were using, accepting Finder’s normal replacement prompt.
  4. Open it and check the version, language, appearance, saved model choices and required account displays. Bundle ID com.silkrd.uma and preference identities are retained. Do not erase preferences, history or caches to upgrade.

Replacing the application does not establish that Sectorium helpers, services or disks are ready, nor promise a complete upgrade of legacy storage components. Resolve a specific system refusal rather than force-killing processes or deleting unrelated files.

Installation problems and rollback

If an old version opens, quit the old copy and launch the chosen installation. Intel Macs and older macOS versions are unsupported by this binary. On a checksum mismatch or macOS security error, stop and redownload; do not bypass the check. To roll back, quit and restore your backed-up App to the same location. App rollback does not revert storage helpers, services or disk data. Preserve user settings and existing images.

Complete bilingual installation manual and troubleshooting

When to use it

Set the model and reasoning effort of Leader, Coder Cluster, Reviewer Cluster and QA separately. Paste the instruction into the Leader responsible for your development folder. AUV never chooses a project, recipient thread or filesystem root.

How to set the team

  1. Open the ThreadOS tab.
  2. Choose a model and Thinking effort in each of the four rows.
  3. Read the exact instruction preview, then select Generate and Copy.
  4. Paste once into your intended Leader conversation. The receiving Leader verifies its managed folder/team binding and submits supported native parameters.
  5. Read its requested, submitted and effective-observed results separately. A manual native Model/Thinking selection may still be required for the receiving Leader itself.

Ultra, with an honest capability boundary

The existing Thinking menu retains Low, Medium, High and Ex High and adds Ultra. Version 0.15.1 uses the versioned sol-luna-ultra-20261010.1 catalog and read-only local Codex CLI model metadata. Its five Sol/Astra/Terra entries allow ultra; GPT-6 Luna does not. This is client-specific capability evidence, not proof about every account or the receiving desktop client. Stale, missing or offline metadata is shown as unverified; deterministic requests remain possible for catalog-supported combinations. A known unsupported combination is blocked without changing your prior selection. Ultra may increase usage and delegate additional agents on eligible hosts. Copying does not run Ultra or change a service tier.

What counts as applied?

Selection → generated/copied instruction → receiving validation → native submission → verified effective state are separate steps. A local parser receipt with pending_native_selection and unknown effective state is not an application ACK. Old versioned TOSCFG requests retain their original catalogs and replay rules; the current compact set_team_models instruction stays target-free.

Troubleshooting and limits

If Copy fails, keep your selections and retry the clipboard action. If a saved value is unsupported, correct that role explicitly; defaults do not replace it. If the receiving host rejects a model or lacks a control, it must report the exact restriction and keep the request unchanged. Never treat a prompt, label or successful send as backend proof. Optional Factorium organizes implementation/review roles where configured; it is not required to use the copy workflow.

Compatibility and references

AUV 0.15.1 requires macOS 14 or newer; the downloadable build targets Apple silicon. Native host capabilities and configured role bindings remain prerequisites for actual model selection. Codex model/list capabilities · Reasoning configuration · Maintained manual.

ThreadOS（线程工）

选择一次，复制一次，由接收 Leader 设置自己的团队。

ThreadOS 是 AUV — Agent Usage Viewer（原名 UMA）内的团队设置工作台。它为现有原生代理生成确定的设置指令，不另建代理引擎，也不自动发送任务。

安装或升级 AUV

AUV 0.15.1 / 构建 2026101002 已包含线程工与分区工，无需分别下载模块 App。

1. 系统要求与正确下载

  • macOS 14 或更新版本，Apple silicon Mac（M 系列芯片）。 在苹果菜单 →“关于本机”确认。本次没有 Intel 下载包。
  • 下载 AUV-0.15.1-build2026101002.zip，以及发布页的 HASHES.txt。不选 GitHub 自动生成的 “Source code” 压缩包；那是源码，不能直接安装。
  • 本版使用 Developer ID Application: SHAOTING HE (C6TUZVJ6SJ) 签名，Apple 公证已接受，公证票据已附加。该记录针对正式发行包，不代表磁盘操作已在你的设备验收。

下载 ZIP 的 SHA-256 应为：

598bd61b8a439dde426b943bee3f84e57ad46bba96b94747405ae687825d505e

可选校验：如果文件保留原名并位于“下载”文件夹，在终端执行下列只读命令，比对输出开头的 64 位值与上述值及 HASHES.txt。校验不相同就停止安装并重新下载。

shasum -a 256 ~/Downloads/AUV-0.15.1-build2026101002.zip

2. 首次安装

  1. 在 Finder 双击 ZIP，解压出 UMA.app。无需打开“显示包内容”，也无需运行源码中的脚本。
  2. 将 UMA.app 拖入内置磁盘的“应用程序”文件夹（/Applications），或个人“应用程序”文件夹（~/Applications）。选择一个位置并持续使用；如果系统要求批准该位置的文件复制，按正常系统流程完成。
  3. 从刚才的安装位置打开应用，不要继续从“下载”或临时解压目录启动。Sectorium 的必要控制链不能依赖将来要弹出的外接硬盘。
  4. 若 macOS 显示正常的首次打开确认，确认来源和版本后按系统界面操作。若报告应用损坏、来源无法验证或被安全策略阻止，先重新下载并核对哈希；不要关闭 Gatekeeper、移除隔离属性或修改系统安全设置来强行启动。
  5. 在 AUV → About AUV（关于 AUV） 核对版本 0.15.1 和构建 2026101002。若只显示版本，可在 Finder 选中安装位置的 UMA.app →“显示简介”复核；详细构建身份也记录在发布页的 RELEASE-MANIFEST.json。显示旧版时，先正常退出旧副本，再从正确安装位置打开。

3. 从 UMA / 较早 AUV 升级

  1. 保存当前工作，使用应用菜单正常退出旧 UMA/AUV；关闭窗口不一定退出菜单栏进程。
  2. 在内置磁盘保留旧 UMA.app 副本，例如单独的备份文件夹，不覆盖唯一的旧版备份。
  3. 将新解压的 UMA.app 复制到原来使用的同一个安装位置，在 Finder 的替换提示中正常完成替换。
  4. 打开新副本，检查版本、语言、主题、既有模型选择和所需账户显示。原 bundle ID com.silkrd.uma 及偏好身份保留；无需删除偏好、历史、缓存或重新建立所有设置。

应用替换不会自动证明 Sectorium 工具、服务或磁盘就绪；也不是对旧存储组件的全面升级承诺。如果正常退出或替换被系统拒绝，处理该具体提示，不要强杀进程或删除无关文件。

安装排错与回退

打开后仍是旧版时，正常退出旧副本，再从选定安装位置启动。Intel Mac 或较旧 macOS 不支持本次二进制包。哈希不符或出现系统安全错误时停止并重新下载，不绕过检查。回退时正常退出，将备份 App 放回原位置；应用回退不回退存储 helper、服务或磁盘数据，不删除用户设置和已有镜像。

完整中英安装手册与排错

适合做什么

分别设置 Leader、Coder Cluster、Reviewer Cluster 和 QA 的模型与思考档位。将指令粘贴给负责你的开发文件夹的 Leader。AUV 不选择项目、接收线程或文件系统根目录。

操作步骤

  1. 打开顶部 ThreadOS（线程工）。
  2. 分别选择四个角色的模型和思考档位。
  3. 查看精确指令预览，点击“生成并复制指令”。
  4. 粘贴给目标 Leader 一次。接收 Leader 核实自己的开发根与团队绑定，再提交受支持的原生参数。
  5. 分别看请求值、已提交值和已验证生效值。接收 Leader 自身仍可能需要用户在原生 Model/Thinking 控件手动选择。

Ultra 的能力边界

原菜单保留低、中、高、极高，新增 Ultra。0.15.1 使用 sol-luna-ultra-20261010.1 版本化目录和只读的本地 Codex CLI 模型元数据。目录中五个 Sol/Astra/Terra 型号允许 ultra，GPT-6 Luna 不允许。这是特定客户端的能力依据，不代表所有账户或接收端桌面应用均支持。离线、缺失或过期元数据标为待核实；目录支持的组合仍可确定地生成请求。已知不支持的组合会被阻止，原选择保留。Ultra 可能增加用量并委派额外代理；复制不会执行模型或改变服务档位。

怎样判断真正完成

当前选择 → 已生成/复制 → 接收端核验 → 原生提交 → 已验证生效，是不同状态。pending_native_selection、effective unknown 的解析回执不是执行成功 ACK。旧版 TOSCFG 按原目录与重放规则继续兼容；当前 set_team_models 指令没有目标项目。

排错与限制

复制失败时保留选择，重试剪贴板动作。旧保存值不受支持时，明确纠正对应角色，默认值不会覆盖它。宿主拒绝模型或缺少控制时，应报告具体限制，不静默替换。消息发送成功、提示词或界面标签都不证明后端生效。Factorium 是可选的实现/审查角色组织方式，不是使用复制流程的前提。
