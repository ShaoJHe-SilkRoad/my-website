ThreadOS

Windows 0.16.3 supports generating and copying instructions; receiving-client integration and live Ultra execution are untested. The screenshot below is macOS 0.15.1. Windows installation.

Choose your team’s models. Copy one instruction. Paste it into your Leader.

ThreadOS is included in AUV. It lets you set the model and thinking level for four roles separately: Leader, Coder Cluster, Reviewer Cluster and QA.

Set up your team

  1. Open ThreadOS in AUV’s top navigation.
  2. Choose a model and thinking level for each role.
  3. Check the instruction preview, then click Generate and Copy.
  4. Paste the instruction into the Leader conversation for your development folder.

The receiving Leader uses its own team. There is no project or thread to select in AUV. Where supported, cluster choices also set the default for their child workers.

Which thinking level should I choose?

Start with Medium. Low asks for less reasoning; High and Ex High ask for more. A higher level can take longer and use more of your allowance.

Ultra is an additional option for supported models. In this release it is available for GPT-6.1 Sol, GPT-6 Sol, GPT-6 Astra, GPT-5.6 Sol and GPT-5.6 Terra, but not GPT-6 Luna. Your receiving client must support the choice too. If AUV marks a choice as unverified, that support has not been confirmed. Ultra command generation was tested; live Ultra execution was not.

How do I know the change worked?

Read the Leader’s reply: it should distinguish what you requested, what it submitted and what it could verify. Copied means the instruction is on your clipboard, not that a model has changed.

If the client cannot change the Leader’s own future-turn model, use that conversation’s native Model and Thinking controls as directed. AUV does not change global defaults or interrupt a running turn.

Common problems

  • Copy failed: your choices are kept. Try copying again.
  • A saved choice is no longer supported: choose another value for that role. AUV does not silently replace it.
  • The Leader reports an unsupported model or missing control: follow its specific explanation; do not assume the change happened.

线程工

Windows 0.16.3 支持生成与复制指令；接收端集成和真实 Ultra 执行未验证。下方截图为 macOS 0.15.1。 Windows 安装指南。

选好团队模型，复制一条指令，粘贴给 Leader。

线程工包含在 AUV 中，可以分别设置四个角色的模型与思考档位：Leader、Coder Cluster、Reviewer Cluster 和 QA。

设置团队

  1. 在 AUV 顶部进入 ThreadOS。
  2. 分别选择四个角色的模型与思考档位。
  3. 查看指令预览，点击“生成并复制指令”。
  4. 粘贴给负责开发目录的 Leader。

接收指令的 Leader 只处理自己的团队。AUV 中无需选择项目或线程；接收端支持时，Cluster 的选择也会用于其子工人的默认设置。

思考档位怎么选？

可以从 Medium（中）开始。Low 请求较少的推理，High 和 Ex High 请求更多推理。档位越高，可能越慢，也可能消耗更多额度。

部分模型还提供 Ultra。本版支持 GPT-6.1 Sol、GPT-6 Sol、GPT-6 Astra、GPT-5.6 Sol 和 GPT-5.6 Terra 的 Ultra，不支持 GPT-6 Luna。接收端也必须支持所选组合。显示“未核实”时，表示支持情况尚未确认。Ultra 指令生成已测试，真实 Ultra 执行未测试。

怎么知道设置成功了？

看 Leader 的回复：它应区分你的请求、实际提交的选择，以及能够确认已生效的选择。“已复制”只表示指令进入了剪贴板，不表示模型已经改变。

如果客户端不能直接修改 Leader 后续回合的模型，请按提示使用该对话的原生 Model 和 Thinking 控件。AUV 不修改全局默认，也不中断正在运行的回合。

常见问题

  • 复制失败：选择会保留，可以再次复制。
  • 保存的选择已不支持：手动修改对应角色，AUV 不会悄悄换成其他值。
  • Leader 提示模型不支持或缺少控件：按它说明的具体限制处理，不要把它当作已经切换成功。
