Sectorium

A development image on your drive. Clear readiness. Deliberate safe ejection.

Sectorium is AUV’s storage workspace, built around the shared HESectorium controller. An APFS sparsebundle is a file-backed virtual development disk on a host filesystem; this is not physical repartitioning or formatting your drive.

Sectorium is in early development. Keep an independent, current backup of important data and evaluate with noncritical test data first. Abnormal disconnection, interrupted operations and unresolved faults can make data unavailable or corrupt it. Do not unplug until the complete intended safe-eject sequence is confirmed. Tests do not cover every device or failure scenario.

Understand the screen

External physical drives are prioritized. Their host volumes and verified development images appear together; internal system/recovery details are secondary. Installation, automation preference, observed service state, current disk readiness and operation progress are separate. A directory existing, a connected drive or a loaded service alone does not mean ready.

Setup and installation

Sectorium is in early development. Keep an independent, current backup of important data and evaluate with noncritical test data first. Abnormal disconnection, interrupted operations and unresolved faults can make data unavailable or corrupt it. Do not unplug until the complete intended safe-eject sequence is confirmed. Tests do not cover every device or failure scenario.
  1. Select the intended physical drive and review the detected image relationship.
  2. Open Sectorium Settings to inspect components, install/repair tools and review automation. Installing tools is distinct from creating a data image; enabling automation is distinct from mounting now.
  3. Explicitly adopt a verified existing development image, or use the supported create flow for a new file-backed image. Review capacity, format and encryption choices; never overwrite an existing image.
  4. Start the development disk and wait for verified readiness. Unknown, read-only or conflicting identities require review before development.
Compatible legacy entry points share one controller and service; installation is not a promise that automation is active.

Everyday operation

For a connected drive with a stopped development image, use Start. For a ready external drive, Safe Eject is the primary departure action: the complete intended sequence must finish before unplugging. Stop affects the virtual development disk; eject concerns the external hardware and its affected volumes. Internal system hardware is never physically ejected through this workflow. Eject does not uninstall software.

Busy, failed or partly complete

Read the failed step and current state in diagnostics. A partially completed eject is not “safe to unplug.” Resolve the reported condition, refresh the observation and use the specifically offered recovery action. Do not delete a lock/journal, kill processes, force-unmount or repeatedly press Resume. Visible occupancy is incomplete evidence; non-forced unmount/eject and the final observed state remain decisive.

Privacy and control boundaries

Device identity, mount relationships and supported I/O metadata are used for storage status; project file contents are not scanned by Sectorium. Physical-drive I/O is not per-project usage. Unknown counters remain unknown; local whole-drive monitoring requires explicit selection. AUV controls its own operations, not all external editors or writers. Required control/log/state components must remain available independently of the drive being ejected.

Sectorium（分区工）

在硬盘上管理虚拟开发盘，明确就绪状态，安全退出。

Sectorium 是 AUV 的存储工作台，底层复用共享 HESectorium 控制器。APFS sparsebundle 是存放在宿主文件系统上的文件型虚拟开发盘，不是修改物理分区或格式化硬盘。

Sectorium 目前处于早期开发阶段。请先独立备份重要数据，并优先使用非关键测试数据评估。异常断连、操作中断或尚未覆盖的故障可能导致数据不可用或损坏；未确认完整安全弹出前，请勿直接拔盘。已完成的测试不代表所有设备和异常场景均已验证。

读懂当前状态

外接物理硬盘优先显示，宿主卷与已核验的虚拟开发盘放在一起；内置系统/恢复信息次要呈现。组件安装、自动化偏好、实际服务状态、磁盘就绪与操作进度分别显示。目录存在、硬盘连接或服务已加载，都不单独等于可以开发。

设置和安装

Sectorium 目前处于早期开发阶段。请先独立备份重要数据，并优先使用非关键测试数据评估。异常断连、操作中断或尚未覆盖的故障可能导致数据不可用或损坏；未确认完整安全弹出前，请勿直接拔盘。已完成的测试不代表所有设备和异常场景均已验证。
  1. 选择目标物理硬盘，核对发现的开发盘关系。
  2. 打开分区工设置，查看组件、安装/修复工具及自动化。安装工具不是创建数据镜像；启用自动化也不是立即挂载。
  3. 明确接纳核验过的现有开发盘，或按已支持的创建流程建立新的文件型镜像。检查容量、格式和加密选项，不覆盖已有镜像。
  4. 启动开发盘，等待真实就绪。未知、只读或身份冲突时先处理原因。
兼容旧入口共用同一控制器和服务；安装完成不代表自动化已运行。

日常使用

硬盘连接但开发盘未启动时使用“启动”。外接开发盘就绪后，“安全弹出”是离开时的主要动作；完整预期链路确认结束后才能拔线。“停止”针对虚拟开发盘，“弹出”针对外接硬件及受影响卷。内置系统硬盘不会进入物理弹出流程；弹出也不是卸载软件。

忙碌、失败或部分完成

在诊断中查看失败步骤和当前状态。部分弹出不等于可拔线。处理报告的原因，重新观察状态，仅使用界面明确提供的恢复动作。不要删除锁/日志、杀进程、强制卸载或反复点继续。未发现可见占用不是安全保证；以非强制卸载/弹出和最终真实状态为准。

隐私和控制范围

分区工使用设备身份、挂载关系及受支持的 I/O 元数据，不扫描项目文件内容。物理硬盘统计不是项目统计；未知计数仍显示未知。本地整盘监测需明确选择。AUV 只能约束自己的操作，不能保证所有编辑器或外部写入都已停止。必要控制、日志与状态组件须能独立于被弹出的硬盘运行。
